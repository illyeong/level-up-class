# 도깨비 사냥 측정기

Windows 10/11용 로컬 화면 인식 프로그램입니다. 게임 일반 측정 패널 또는 절전 화면의 경과 시간·누적 골드·처치 수를 읽습니다. 절전 화면은 맵 이름도 자동 인식합니다. 게임에 입력하거나 게임 파일을 수정하지 않습니다. 화면과 인식값을 외부 서버로 보내지 않습니다.

## 일반 화면 측정 (v1.6)

1. 게임에서 일반 화면의 사냥 측정을 시작합니다.
2. 프로그램의 **화면 종류 → 일반 측정**을 선택합니다.
3. **통합 영역 지정**으로 맨 위 처치 아이콘 줄부터 맨 아래 **측정 종료 버튼**까지, 패널 전체를 한 번에 선택합니다. 보내주신 270×241 이미지처럼 좌우 테두리에 맞추고 바깥 여백을 최소화하세요. 이번 화면에서는 가방·아이템 영역도 포함합니다.
4. **자동 인식 시작**을 누릅니다. 맨 위 오른쪽 처치 수, 그 아래 오른쪽 골드, 아래 버튼의 경과 시간을 읽습니다. 가방 용량과 아이템 개수는 계산에서 제외합니다.
5. 패널에 맵 이름이 없으므로 **일반 측정 맵 이름**에 기록용 이름을 선택 입력합니다. 맵을 옮겼다면 입력값도 변경하세요. 비워두면 맵 없이 기록되며, 기록 창에서는 미인식으로 표시합니다.

일반 측정/절전 화면 영역은 각각 저장됩니다. 모드를 바꾸면 자동 인식을 중지하고 최근 측정 구간을 초기화합니다. 기존 v1.5 영역은 절전 화면용으로 유지됩니다. 프로그램은 게임의 측정 시작/종료 버튼을 조작하지 않습니다. 13초 보정은 적용하지 않습니다.

## 절전 화면 사용 방법

1. `DokkaebiMeter.exe`를 실행합니다.
2. 게임을 절전 화면으로 두고 프로그램에서 **화면 종류 → 절전 화면**을 선택합니다.
3. **통합 영역 지정**을 누르면 각 모니터에 별도 선택 화면이 나타납니다. 게임이 보이는 모니터에서 **맵 이름 → 시간 → 골드 → 처치 수 네 줄**을 한 사각형으로 드래그합니다. 맵 글자가 전부 들어가도록 좌우 여유를 두고, 네 줄의 위아래 여백을 비슷하게 맞추세요. 왼쪽 아이콘과 아래 가방은 제외하세요. Esc로 취소합니다.
4. **자동 인식 시작**을 누릅니다. 기본 5초 간격으로 갱신합니다.
5. 게임 창을 이동하거나 크기를 바꾸면 영역을 다시 지정합니다.

**v1.5 변경**: 한 번 지정한 영역을 한 장으로 캡처해 맵과 숫자를 함께 읽습니다. 이전의 숫자/맵 별도 영역은 사용하지 않으므로 업데이트 후 통합 영역을 한 번 다시 지정하세요. 이후에는 저장된 통합 영역을 불러옵니다. 13초 보정 버튼과 새 기록/CSV의 시간 보정은 제거했습니다. 예전 보정 설정이 남아 있어도 적용하지 않습니다.

메인 화면에 인식한 맵 이름을 표시하고, 최근 10개 기록 및 CSV의 `맵 이름` 항목에 당시 이름을 저장합니다. 맵이 없던 기존 기록은 그대로 유지하며 `미인식`으로 표시합니다. 맵 인식이 실패해도 숫자 기록은 계속 저장하고, 이전 맵 이름으로 대신 채우지 않습니다. 글자가 잘못 인식될 수 있으므로 메인 화면의 맵 이름을 확인하고 필요하면 영역을 다시 지정하세요.

맵 이름이 변경되면 최근 1분 측정은 새로 모읍니다. 전체 평균은 여전히 게임에 표시된 절전 누적 시간/수치 기준입니다. 맵별 순수 효율을 비교하려면 맵을 옮긴 뒤 게임 절전 누적값도 새로 시작하세요.

게임 화면이 실제 모니터에 보여야 합니다. 최소화하거나 다른 창으로 숫자를 가리면 읽을 수 없습니다. 측정기 자체도 숫자 위에 놓지 마세요. 검게 캡처되면 게임을 창 모드/테두리 없는 창 모드로 시도하세요.

## 수치의 의미

- 전체 평균: `화면의 누적값 × 60 ÷ 화면의 경과 초`. 프로그램을 늦게 실행해도 절전 시작 이후의 평균을 보여줍니다.
- 최근 약 1분: 최소 60초, 최대 80초 간격의 유효한 기록 두 개에서 차이를 계산하고 분당으로 환산합니다. 시작 직후에는 `—`로 표시합니다.
- 새 측정: 최근 변화량 기록을 초기화합니다. 게임의 누적 시간/수치는 변경하지 않습니다.
- 시간 초기화는 연속 두 번의 증가하는 새 기록으로 확인한 뒤 새 세션으로 처리합니다.
- OCR 오류 시 마지막 유효값을 유지하고 오류 상태를 표시합니다. 원본 영역 미리보기와 인식 숫자를 함께 확인하세요. 숫자로 잘못 읽힌 오인식까지 모두 검출할 수는 없습니다.
- CSV에는 해당 실행 중의 성공한 인식 기록을 저장합니다. 종료하면 미저장 기록은 사라집니다.
- **이전 기록 (N/10)**: 최근 성공한 자동 인식 10개를 별도 창에서 최신순으로 봅니다. 측정 시각·맵 이름·화면 시간·전체 평균 골드/처치·최근 1분 골드/처치를 표시합니다. 행을 누르면 누적값도 확인할 수 있습니다. 새 인식이 추가되면 열린 기록 창도 갱신됩니다.
- 최근 10개 기록은 `%LOCALAPPDATA%\DokkaebiMeter\history.json`에 자동 저장되어 재실행해도 남습니다. 오류 인식 및 같은 시간/값의 반복 인식은 추가하지 않습니다. 11번째부터 가장 오래된 기록이 빠집니다. 이전 버전의 기록은 당시 계산값을 유지하며, 보정했던 기록은 행 선택 시 안내합니다. 이전 버전에서 이미 종료한 기록은 복구되지 않습니다.
- 영역 설정만 `%LOCALAPPDATA%\DokkaebiMeter\settings.json`에 저장됩니다. 시작 버튼을 눌러야 화면 인식이 시작됩니다.

Windows에 한국어 OCR 언어 기능이 있어야 한국어 게임의 시간 숫자를 안정적으로 읽습니다. 이 PC에서는 한국어 OCR로 첨부 화면을 검증했습니다. OCR 엔진이 없으면 Windows 언어 설정에서 한국어의 광학 문자 인식 기능을 설치하세요.

## 개발 / 검증

Python 3.13 환경에서:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m unittest -v
.venv/Scripts/python.exe meter.py
.venv/Scripts/python.exe -m PyInstaller --noconfirm --clean --onedir --windowed --name DokkaebiMeter --manifest meter.manifest --collect-all winrt meter.py
```

빌드 결과의 `dist/DokkaebiMeter` 폴더 전체를 함께 배포합니다. EXE만 따로 옮기면 실행되지 않습니다.

v1.1: 서로 다른 크기·배율·높이의 모니터를 각각의 선택 창으로 처리합니다. 왼쪽 모니터의 음수 좌표와 캡처 작업 스레드의 DPI를 보정합니다. 이전 버전의 저장 좌표는 사용하지 않으므로 최초 실행 시 영역을 다시 지정하세요.

다중 모니터 검증: 실제 연결된 3개 모니터 `(-1920,136)-(0,1216)`, `(0,0)-(2560,1440)`, `(2560,230)-(4480,1310)`에서 각각 선택 창을 배치하고, 선택 좌표 변환·작업 스레드 캡처·OCR 결과 일치를 확인했습니다. 선택 취소 시 세 창 모두 닫히는 것도 확인했습니다. 좌표·계산·기록·설정 전환 및 캡처 경로를 테스트합니다. `check_screens.py 원본스크린샷경로`로 맵과 숫자 네 줄을 이용한 통합 검증을 재실행할 수 있습니다.

검증: 제공된 절전 화면에서 566초·35,836골드·693마리를 인식했으며, 원본의 75%·100%·125%·150%·200% 크기에서도 같은 결과를 확인했습니다. 이 화면을 테스트 창에 표시한 자동 캡처→OCR→화면 갱신 경로와, 빌드한 EXE의 이미지 OCR도 확인했습니다. 실제 게임의 창 모드·캡처 방식에 따른 차이는 사용 환경에서 확인해야 합니다.

v1.5 검증: 통합 영역 3가지 여백 × 5가지 크기에서 맵·시간·골드·처치 일치, 테스트 20개 통과. 현재 연결된 모니터 2개 각각에서 통합 영역 선택·스레드 캡처·OCR·취소를 확인했습니다. 위의 3개 모니터 검증은 v1.1 당시 기록입니다.


v1.6 검증: 제공된 일반 측정 화면의 11초·984골드·19마리를 4가지 여백 × 5가지 크기로 확인했습니다. 일반/절전 모드별 영역, 기록, CSV, 이전 설정 호환을 포함한 테스트 21개가 통과했습니다. UI 위치나 배치가 달라지면 영역을 다시 지정해야 하며, 큰 배치 변경은 인식 방식 조정이 필요합니다.
